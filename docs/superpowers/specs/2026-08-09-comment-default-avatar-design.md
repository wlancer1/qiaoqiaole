# 评论默认头像设计

## 目标

评论区优先展示评论作者已设置的真实头像；作者没有设置头像、头像值为空或头像图片加载失败时，展示统一的用户轮廓图标，不再使用昵称首字作为默认头像。

## 根因

评论接口当前只返回作者 ID 和名称，没有从 `users.avatar_url` 返回头像地址。H5 评论组件因此无法区分“用户有头像”和“用户没有头像”，并固定用作者昵称首字渲染占位。该占位也没有稳定的默认头像视觉。

## 方案

### API 数据

- 评论列表查询从 `users.avatar_url` 读取头像，并始终以字段 `authorAvatar` 返回。
- 新建评论时读取同一字段，并在创建成功响应的评论对象中始终返回 `authorAvatar`。
- 数据库不保存额外的评论头像副本；评论始终读取用户当前头像，避免重复数据。
- 两个接口使用同一响应契约：头像为去除首尾空白后的非空地址字符串，否则为 `null`；不得返回空字符串或省略字段。

### H5 展示

- 扩展 `CommunityComment`，增加必有字段 `authorAvatar: string | null`。
- 评论头像封装成一个小型展示组件：存在可用地址时渲染圆形图片，否则渲染项目现有图标体系中的用户轮廓图标。
- 图片触发加载错误时，仅让当前评论头像切换到同一个用户轮廓图标，避免破图且不影响其他评论。
- 默认图标使用固定的浅色圆形底和清晰前景色，并保持现有评论头像尺寸与布局不变。
- 头像图片使用空 `alt`，默认图标使用 `aria-hidden="true"`；相邻作者名继续承担可访问名称，避免重复播报。

## 数据流

1. API 从评论记录关联到作者用户记录。
2. API 返回 `authorAvatar`。
3. H5 将字段传给评论头像展示组件。
4. 有效图片成功加载时显示图片；缺少地址或加载失败时显示统一用户图标。

## 错误与边界处理

- `null`、`undefined`、空字符串和仅空白字符串都视为未设置头像。
- 图片地址存在但加载失败时只影响该条评论头像，并在组件内回退为默认图标。
- 作者名称和评论主体的现有行为保持不变。

## 测试

- API 测试夹具直接为测试用户写入 `users.avatar_url`，确认新建评论响应与随后评论列表响应都始终包含 `authorAvatar`，并返回相同的非空地址。
- API 测试另行确认未设置、空字符串或纯空白头像时，两个响应均包含 `authorAvatar: null`。
- H5 组件测试确认无头像评论渲染统一用户图标，不再渲染昵称首字。
- H5 组件测试确认有头像评论渲染真实图片。
- Playwright 浏览器测试让一条评论头像图片加载失败，确认该图片被默认用户图标替换，且其他评论头像不受影响；静态组件测试不承担图片 `error` 事件验证。
- 保留并运行社区 API、H5 图纸详情相关测试，最后执行类型检查/构建验证。

## 非目标

- 不新增头像上传或个人资料编辑能力。
- 不修改社区稿件作者头像、消息头像或个人中心头像。
- 不批量写入或迁移用户头像数据。

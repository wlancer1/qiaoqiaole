# 社区真实数据、评论与分享设计

## 背景

H5 端当前的热门模板、发现页稿件和详情页评论使用前端静态数据。需要改为真实数据，并把用户保存的作品接入社区：用户保存作品时可以选择分享到社区，分享后的作品进入发现和热门模板；同一作品不能重复分享；热门模板按点赞数排序；登录用户可以点赞和评论。

## 目标与非目标

### 目标

- 以 `projects` 作为作品唯一数据源，不复制出另一份社区稿件快照。
- 只有已保存且主动分享的作品才对社区可见。
- 发现页、热门模板和图纸详情读取 API 真实数据。
- 登录用户可以对社区作品点赞和发表评论。
- 数据库层保证同一用户不能重复点赞，同一作品不能重复分享。

### 非目标

- 本次不实现关注、消息通知、评论回复、评论删除和内容审核后台。
- 本次不改变现有画布编辑和作品图片上传流程。
- 本次不引入新的数据库产品，继续使用现有 sql.js + SQLite。

## 数据模型

在 `projects` 表增加社区字段：

- `shared_to_community`：整数布尔值，默认 `0`。
- `shared_at`：ISO 8601 时间，可为空。
- `likes_count`：整数，默认 `0`。

新增 `project_likes` 表：

- `project_id`、`user_id`、`created_at`。
- 主键为 `(project_id, user_id)`，并关联 `projects` 和 `users`。

新增 `project_comments` 表：

- `id`、`project_id`、`user_id`、`content`、`created_at`。
- 关联 `projects` 和 `users`。
- 评论内容由 API trim 后限制长度，空评论拒绝写入。

数据库迁移使用现有的“创建表 + 尝试 ALTER COLUMN”兼容模式，避免覆盖已有 SQLite 文件。

## API 与数据流

所有社区读写接口都复用现有 Bearer session。社区列表读取也要求登录，以便返回当前用户是否已点赞；未登录用户由前端在访问社区操作时引导登录。

- `GET /api/community/posts?sort=hot|latest`
  - 只返回 `shared_to_community = 1` 的作品。
  - `hot` 按 `likes_count DESC, shared_at DESC`，`latest` 按 `shared_at DESC`。
  - 返回作品图片、尺寸、作者用户名、点赞数、评论数、分享时间和当前用户点赞状态。
- `GET /api/community/posts/:projectId/comments`
  - 返回该作品评论及评论作者用户名，按创建时间倒序。
- `POST /api/community/posts/:projectId/like`
  - 作品未分享时拒绝；已点赞时返回当前状态，不重复插入；首次点赞写入记录并递增 `likes_count`。
- `POST /api/community/posts/:projectId/comments`
  - 校验作品已分享和评论内容长度；写入评论并返回新评论。
- `POST /api/projects/:projectId/share`
  - 仅允许作品拥有者调用。
  - 首次分享更新作品状态和时间；已分享时返回同一作品状态，不创建重复社区内容。

保存弹窗的流程为：先保存作品和画布快照，保存成功且勾选“分享到社区”后调用分享接口。分享失败不回滚已保存的作品，页面提示用户可在“我的作品”中重试分享。

## 前端交互

- 删除发现页、热门模板和详情页中的静态稿件、静态评论和静态计数。
- 进入发现页时请求热门社区稿件；加载中显示骨架或轻量加载状态；无数据显示真实空状态。
- 首页“热门模板”复用社区列表数据，按点赞数降序取前 3 条，并使用作品缩略图；无数据时显示空状态，不伪造卡片。
- 详情页从真实稿件进入，加载评论和当前用户点赞状态。
- 点赞按钮使用乐观更新；接口失败时恢复原状态并显示错误。
- 评论输入框只对登录用户提供提交能力；未登录时点击输入区域引导登录；提交成功后立即追加真实返回的评论。
- 保存作品弹窗增加社区分享开关：新作品默认关闭；已分享作品显示“已分享到社区”并禁用重复分享动作。
- 分享成功后显示明确状态，并在下一次进入发现页时可见。

## 错误处理与一致性

- API 统一返回现有格式 `{ error, message }`。
- 点赞计数以数据库记录为准；服务端只在新插入点赞记录成功时递增计数。
- 作品分享接口对重复请求保持幂等。
- 社区列表的评论数使用数据库聚合结果，避免前端静态计数。
- 图片沿用现有 COS / 本地资源解析逻辑，不新增图片存储路径。

## 测试策略

- API 测试：分享权限、重复分享幂等、未分享作品不可点赞/评论、重复点赞唯一约束、评论内容校验、热门排序。
- 前端单元测试：社区列表映射、热门模板按点赞排序、分享状态显示、评论提交后的列表更新。
- E2E：登录 → 保存作品 → 勾选分享到社区 → 发现页出现 → 详情点赞 → 发布评论 → 刷新后数据仍存在；重复分享和重复点赞不增加数量。
- 构建验证：`npm test`、`npm run build`，必要时运行相关 Playwright 用例。

## 实施边界

实现优先复用现有 `requestApi`、登录状态、作品保存、发现页和详情页组件。只做社区功能所需的类型、API、数据迁移和 UI 状态调整，不重构无关画布与仓库模块。

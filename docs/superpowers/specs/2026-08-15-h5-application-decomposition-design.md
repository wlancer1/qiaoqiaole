# H5 应用全量分层重构设计

## 目标

将 `apps/h5/src/H5App.tsx` 从 3659 行的应用协调器拆为按职责和领域划分的模块。重构不改变已有路由、接口、页面视觉、弹窗交互、认证语义或异步提示规则；最终入口只保留应用装配职责。

## 边界与约束

- 页面导航继续使用 React Router；不得重新引入基于 `screen`、`activeTab` 的页面切换状态。
- 服务端数据和跨页缓存优先使用 RTK Query；跨组件但非服务端的稳定状态使用按领域拆分的 Redux slice。
- 草稿、输入、文件、画布操作、计时器、DOM ref、动画和弹窗局部交互保持组件本地状态或局部 Context，禁止写入 Redux。
- 跨页面弹窗、确认框、操作 Sheet 和全局提示继续挂载在不会随页面卸载的应用级覆盖层；锁滚动、遮罩和键盘行为保持不变。
- 旧异步响应必须继续通过请求序号、取消标记或 Router scope 校验被丢弃，不能将旧页面提示写到新页面。
- 每次迁移先建立行为测试，验证后再提交；不改变 API 协议或后端实现。

## 目标结构

```
apps/h5/src/
  app/
    AppBootstrap.tsx        # Provider、Router 和应用初始化
    H5AppShell.tsx          # 路由出口与应用级 Overlay
    routes/                 # 路由注册、认证守卫、重定向
    overlays/               # 全局提示、登录入口、ConfirmDialog、Sheet 宿主
  features/
    auth/                   # 登录、会话恢复、退出、登录闸门
    projects/               # 项目列表、详情、文件夹与项目操作协调
    community/              # 帖子、作者页、评论、通知与社交操作
    warehouse/              # 仓库列表、仓库详情与库存操作协调
    beading/                # 拼豆会话启动、恢复、结束和跨页入口
  pages/
    ...                     # 只读取路由参数，组合领域 hook 与展示组件
  store/
    ...                     # RTK Query、按领域 slice、selector、thunk
```

`H5App.tsx` 迁移完成后只保留向后兼容的薄入口（或由 `AppBootstrap` 直接替代），不再承载业务请求、页面切换或跨领域状态。

## 领域职责

| 模块 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| `app/routes` | 路径、参数解析、登录保护、重定向与 Router scope | 领域请求和页面展示状态 |
| `app/overlays` | 跨路由弹窗、确认框、全局提示的统一挂载 | 页面私有表单和画布交互 |
| `features/auth` | 登录、恢复会话、退出、返回目标 | 项目/社区页面的业务请求 |
| `features/projects` | 项目查询、文件夹、创建/保存/删除、编辑入口 | 编辑器内部画布状态 |
| `features/community` | 帖子、标签、作者、评论、点赞、关注、通知 | 社区 UI 组件的视觉细节 |
| `features/warehouse` | 仓库、库存、物料操作 | 拼豆画布工具状态 |
| `features/beading` | 会话生命周期与跨页恢复入口 | Pointer/缩放等高频交互 |

## 数据与导航流

1. Router 解析 URL，并给出当前 scope；需要认证的路由先通过认证闸门。
2. 页面从路由参数取得资源 ID、Tab、筛选和分页；页面不能依赖上页残留对象。
3. 领域 hook 通过 RTK Query endpoint 或已存在的领域 thunk 请求数据，并只暴露页面需要的命令和派生状态。
4. 页面私有操作使用组件本地 state；领域完成的结果通过领域 action 更新共享 state 或使 RTK Query tag 失效。
5. 页面提示带上创建时捕获的 Router scope；路由变化后旧提示立即清除，晚到响应不再提交。
6. 跨路由弹窗由 `H5AppShell` 的 Overlay 承载，页面通过显式 action 或 Context 请求打开，不能把弹窗 JSX 留在会被卸载的页面分支中。

## 迁移顺序

1. **应用壳和路由**：建立 `H5AppShell`、路由出口和 Overlay 宿主，移除入口中遗留的页面分支。
2. **认证**：完成现有认证协调器接入，将登录门、登录弹窗状态和返回目标收敛到 `features/auth`。
3. **项目**：将项目列表、分页、文件夹、保存和编辑跳转迁入项目领域；编辑器保持页面私有交互。
4. **社区**：以既有 `useCommunityDomain` 为基础完成所有社区协调逻辑迁移，页面只做组合。
5. **仓库与拼豆**：迁移资源加载、会话启动和恢复协调；画布与拼豆高频交互不入 Redux。
6. **编辑器、分图与收尾**：迁移跨页面命令、清理死代码和遗留 props，将入口压缩为薄壳。

每个阶段可独立发布：行为不变、测试先行、构建通过后单独提交。阶段之间不要求一次性变更所有页面。

## 错误处理与兼容性

- 401 继续触发统一会话失效处理与登录入口，不允许各页面自行重置全局认证状态。
- 404/资源不存在保留原有页面提示与返回行为。
- 所有异步加载有 loading、error 和过期响应保护；没有以 Redux 替代这些局部生命周期状态。
- 旧路径、刷新和浏览器前进/后退必须可用；资源详情使用路由 ID 重新获取所需数据。

## 验证策略

- 每个新增 slice 覆盖 reducer、selector 和适用的 thunk/缓存失效路径。
- 每个领域 hook 覆盖成功、失败、取消或过期响应，以及未登录入口（如适用）。
- 路由测试覆盖深链接、未登录跳转、登录后返回、路由变化清理旧提示。
- Overlay 测试覆盖打开、取消、确认、遮罩不穿透和滚动锁定。
- 每个阶段至少运行对应 Vitest 测试、`npm run build:h5` 和 `git diff --check`；最终运行 H5 全量测试。

## 完成标准

- `H5App.tsx` 不再包含领域请求、项目/社区/仓库/拼豆的页面状态或基于变量的页面分支。
- 领域代码拥有明确模块边界，并由路由页面组合。
- 路由、认证、提示和弹窗行为与当前版本保持一致。
- 所有新增或迁移的状态符合 Redux 可序列化约束。
- H5 测试、构建和 diff 检查全部通过。

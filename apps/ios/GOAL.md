## 唯一目标

在不破坏现有 H5/API 行为及用户未提交修改的前提下，将 `apps/h5` 的完整产品迁移为 SwiftUI/UIKit 原生 iOS App，并用自动化测试、真机/模拟器运行证据和逐页对照证明功能及视觉达到本文件定义的等价标准。

## 最终目标

将 [`apps/h5`](../h5) 迁移为可上架的 **原生 iOS App**。iOS 版以 H5 当前线上产品为唯一功能、交互和视觉参考；不得将其降级成仅包含画布或 STL 导出的简化 Demo，也不得使用 WebView / Capacitor 承载 H5 页面。

## 来源优先级

发生冲突时按以下顺序处理：

1. 用户在当前会话中的明确要求；
2. 根目录及 iOS 目录的 `AGENTS.md`；
3. H5 行为测试和 API 测试；
4. H5 当前实现与 CSS；
5. 本文件中的阶段摘要；
6. 当前简化 iOS MVP。

当前 iOS MVP 只可复用经过对照验证的代码，不是产品行为或视觉的来源。

## 成功定义

在相同登录状态、相同 API 数据及相同输入下，用户能够在 iOS 上完成与 H5 等价的主要任务，看到等价的信息、操作入口、确认行为和结果。界面应遵循 iOS 的安全区与系统交互，但信息架构、文案、颜色、层级、关键尺寸和流程必须与 H5 对齐。

“等价”具体指：

- H5 的每个正式路由均有可导航、可深链接恢复的原生目的页，不允许空白页、占位页或仅展示静态文案。
- H5 测试覆盖的成功、失败、取消、返回、登录拦截、异步晚到和弹窗防穿透行为，在 iOS 有对应实现与测试。
- 同一 API fixture 下，列表字段、分页、详情内容、计数和状态变化一致；列表不得为了方便加载详情大字段。
- 同一图片和参数下，裁剪范围、网格尺寸、颜色代码、豆子数量以及 STL/图纸的关键输出可通过契约测试比较。
- 视觉对照覆盖 320、375、414 pt 等价手机宽度和至少一个 iPad/宽屏尺寸；除系统控件必要差异外，布局结构、文案、颜色、间距、圆角、遮罩与层级一致。

## 范围与页面对照

| H5 路径 / 模块 | iOS 原生目标 |
| --- | --- |
| `/`、`/discover`、`/messages`、`/profile` | 首页四个 Tab：创作首页、发现、消息、个人中心 |
| `/split`、`/split/crop`、`/split/preview` | 选图、裁剪、分图参数、生成预览、豆子清单完整流程 |
| `/projects` | 作品分页列表、文件夹筛选、创建/移动/删除/分享操作 |
| `/projects/:id/edit`、`/canvas` | 参考图、缩放平移、准确标尺、画笔/填充/吸管、调色、撤销重做、保存及导出 |
| `/projects/:id/beading`、`/beading` | 拼豆会话、颜色轨、计时、进度、库存核验、完成和退出流程 |
| `/warehouses`、`/warehouses/:id` | 仓库列表、创建仓库、库存与仓库详情 |
| 社区作品/作者/关注路径 | 发现列表、详情、评论回复、点赞、关注、作者页、消息跳转 |
| 登录、编辑资料、协议、隐私政策 | 原生登录/资料编辑弹窗、认证返回、法律页面 |

完整路由清单以 `apps/h5/src/app/h5Routes.ts` 为准。新增或删除 H5 正式路由后，必须同步更新 iOS 路由、测试和本表，不得静默遗漏。

## 非协商要求

1. **原生实现**：页面使用 SwiftUI/UIKit；高频画布交互使用原生绘制与手势。禁止用 WebView 偷换实现。
2. **H5 行为一致**：路由/导航状态、列表摘要与详情请求分离、登录保护、异步取消、错误与成功提示均要保留对应语义。
3. **API 一致**：继续使用现有 API 与资源 ID；直接打开某一作品、刷新或从通知跳转时，必须按 ID 拉取详情，不能依赖上一页内存。
4. **编辑器一致**：基础单格为 14px 等价视觉单位；标尺槽为 22px 等价视觉单位；缩放后标尺必须按实际可见格子的屏幕中心计算。
5. **弹窗一致**：所有 Sheet、确认框和全屏覆盖层都应阻挡背景点击与滚动；破坏性操作必须二次确认；异步期间禁止重复提交。
6. **导出可用**：STL、图纸等文件必须保存至 App 容器并调用 iOS 系统分享/文件流程，不能依赖浏览器下载行为。
7. **无功能降级**：当前 iOS MVP 中未覆盖的 H5 功能都属于待实现，不得标记为完成。
8. **保留用户修改**：开始每个检查点前运行 `git status --short`；不得覆盖、回滚或格式化与当前检查点无关的用户修改，不得创建新分支或 worktree。
9. **测试先行**：迁移行为前先添加最小失败测试或契约 fixture；实现后运行该检查点的定向测试和全量 iOS 测试。
10. **无占位完成**：页面骨架、静态假数据、空回调、`TODO`、仅能预览的按钮均不得计入完成。
11. **依赖克制**：新增三方 iOS 依赖前必须证明系统框架无法合理满足需求，并在 `PROGRESS.md` 记录原因、版本与许可。
12. **原生状态边界**：导航状态由 SwiftUI Navigation/深链接层管理；服务端数据由按领域拆分的 repository/client 管理；画布手势、临时弹窗、草稿等短生命周期状态保持本地，禁止创建无边界的全局状态对象。

## 实施阶段与验收

### P0 — 基座与设计系统

- 建立原生导航、深链接、Tab、登录门禁、全局覆盖层和页面级提示作用域。
- 将 H5 的颜色、字体、圆角、间距、安全区规范映射为 Swift Token。
- 验收：主要 H5 路径均有对应 iOS 路由，前进、返回、深链接与未登录拦截正确。
- 证据：路由单元测试、未登录/已登录导航测试、至少四个首页 Tab 的模拟器截图。

### P1 — 创作与作品闭环

- 完成首页、图片导入、分图三步流程、作品列表/文件夹与保存。
- 验收：从选图到生成项目、保存到作品列表、重新打开编辑均可完成。
- 证据：固定图片 fixture 的分图契约测试、作品列表/详情请求测试、完整 UI 流程截图或录屏。

### P2 — 原生编辑器与导出

- 完成带标尺的缩放画布、参考图、编辑工具、调色、历史、豆子清单、图纸/STL 导出。
- 验收：与 H5 使用同一输入时，网格、颜色统计、导出文本和编辑结果一致。
- 证据：同 fixture 跨 TS/Swift 的输出对照、撤销重做/缩放标尺测试、模拟器导出文件检查。

### P3 — 拼豆与仓库

- 完成拼豆会话、颜色进度、计时、库存核验与仓库管理。
- 验收：会话可暂停/恢复，库存扣减、完成和退出流程与 H5 API 行为一致。
- 证据：会话恢复、库存不足、扣减成功/失败/取消和异步晚到测试。

### P4 — 社区与发布准备

- 完成发现、详情、评论、关注、消息、资料编辑与法律页。
- 完成图标、启动页、隐私说明、无障碍、真机性能、TestFlight 和审核物料。
- 验收：TestFlight 真机回归通过，审核人员可不依赖开发环境完成所有核心流程。
- 证据：发布构建、TestFlight build 号、隐私清单、审核演示账号/模式和真机回归记录。

## 每个检查点的执行循环

1. 读取本阶段涉及的 H5 页面、CSS、测试、状态和 API 契约。
2. 在 `PROGRESS.md` 写清本次范围、H5 参考文件、已存在的用户修改和预期验证。
3. 先补原生测试或跨端 fixture，再实现最小完整垂直切片。
4. 构建并运行定向测试；在 Simulator 中实际走通入口、取消、确认、错误和返回。
5. 将 iOS 截图与同尺寸 H5 参考逐页对照；记录差异并继续修正，不能以“原生风格不同”为由跳过产品结构差异。
6. 运行本文件规定的阶段验证和 `git diff --check`。
7. 只有证据齐全时才把检查点标为完成，并在 `PROGRESS.md` 记录验证命令、结果和剩余风险。

## 验证命令

基础构建（每个检查点必须通过）：

```sh
xcodebuild -project apps/ios/QiaoQiaoLe.xcodeproj \
  -scheme QiaoQiaoLe \
  -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  build CODE_SIGNING_ALLOWED=NO
```

单元测试（选择本机实际存在的模拟器名称；不得因为设备名不同跳过）：

```sh
xcrun simctl list devices available
xcodebuild -project apps/ios/QiaoQiaoLe.xcodeproj \
  -scheme QiaoQiaoLe \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=<available iPhone>' \
  test CODE_SIGNING_ALLOWED=NO
```

如果修改共享算法、H5 fixture 或 API 契约，还必须按影响范围运行：

```sh
npm test
npm run build:h5
```

所有检查点结束前运行：

```sh
git diff --check
git status --short
```

测试或构建若因开始前已有问题失败，必须在 `PROGRESS.md` 记录基线证据和本次影响；不得改动无关业务来制造全绿结果。

## 进度记录合同

`PROGRESS.md` 是事实日志而非愿望清单。每次持续目标恢复时先读，结束检查点前更新，至少包含：

- 当前阶段与垂直切片；
- 已完成且有证据的事项；
- H5 → iOS 对照文件；
- 执行过的命令及通过/失败结果；
- 已知差异、既有失败和下一步；
- 是否命中暂停条件。

不得只根据代码存在就标记完成；没有测试和可运行证据的条目保持未完成。

## 暂停条件

仅在以下情况暂停目标并向用户报告具体证据与所需决定：

- 需要用户提供 Apple Developer Team、证书、App Store Connect 权限、生产密钥或审核账号；
- H5 实现、测试和 API 契约互相冲突，且不同选择会改变用户可见行为；
- 必须执行删除数据、数据库迁移、外部发布、付费服务开通等未获授权的高影响操作；
- 工作区已有修改与当前文件直接重叠，无法在不覆盖用户修改的情况下安全继续；
- 连续验证证明系统框架无法满足关键能力，必须由用户批准新增高影响依赖或更改技术路线。

遇到普通编译错误、测试失败、实现困难或耗时较长时不得暂停，应继续诊断、修复和验证。

## 最终停止条件

只有以下条件全部满足，Codex 才能将目标标记为完成：

1. P0–P4 全部完成，`PROGRESS.md` 对每阶段都有验证证据。
2. H5 正式路由清单中的每个页面均有完整原生实现，无占位内容和无效操作。
3. 核心跨端 fixture、全部 iOS 测试、iOS Simulator build 和受影响的 H5/API 测试通过。
4. 320/375/414 pt 与 iPad/宽屏的逐页视觉对照完成，未解决差异均获得用户明确接受。
5. 图片导入、分图、保存、重新打开、编辑、拼豆、库存、社区和导出等端到端流程在真机或 TestFlight 上通过。
6. App 图标、启动体验、隐私清单、权限用途说明、无障碍名称、发布签名和 App Store 审核资料齐备。
7. `git diff --check` 通过，工作区中原有用户修改未被覆盖，并提交最终验证摘要。

在缺少开发者账号等外部条件时，只能标记为命中暂停条件，不能将“代码完成”等同于整个目标完成。
